## 用户需求

将已完成的一轮移动端可访问性评审结论（`mobile-accessibility-audit.md`）转化为可执行的阶段性修复计划，覆盖性能、视觉交互、适配兼容、可访问性、移动端特有交互五个维度。计划须明确标注每一步的**责任智能体**与**预计完成时间**。

## 核心修复范围

- P0（必改）：`index.html` 缺 `viewport-fit=cover` 与 `interactive-widget`；`AppLayout` 顶栏与页面各自渲染 `<h1>` 导致每页双 h1；`Dialog` 关闭按钮命中区仅 16px（不达 44px）。
- P1：移除 `globals.css` 重复阻塞的字体 `@import`；`100vh` 改 `100dvh`；补充 `color-scheme: dark` 与全局 `touch-action: manipulation`、点按高亮处理。
- P2：新增 `prefers-contrast: high` 高对比适配；将 `axe-core`/`jest-axe` 自动化可访问性测试接入 `pnpm verify` 回归门禁。
- P3：屏幕阅读器与键盘导航全量手动 QA（验证双 h1 整改、焦点顺序、live region 播报）。

## 责任分工

- `platform-dev`（基础层）：布局/路由/shared/CI，负责 index.html、AppLayout、Dialog、globals.css 性能适配项与 CI 门禁。
- `ui-ux-dev`（基础层）：设计语言/响应式/可访问性，负责触控手感、安全区复核、高对比模式与手动 QA。

## 技术栈与现状

- React 19 + Vite 8 + TS 7 + Tailwind v4 + Radix（Dialog）+ framer-motion；纯前端 PWA，无后端。
- 既有良好基础：路由 `React.lazy()` + `manualChunks` 分包、`designTokenGuard` 调色板守卫、`focus-visible` 焦点环、Radix Dialog 语义结构、`<main>/<header>/<nav>` 地标、`lang="zh-CN"`。计划仅做**增量整改**，不重构。

## 实施策略

按 P0→P3 渐进，每步对应单一逻辑单元、独立可验证，遵循项目「Surgical Changes」原则。

1. **布局元信息（P0）**：`index.html` 的 `viewport` 增加 `viewport-fit=cover` 与 `interactive-widget=resizes-content`，使 `MobileNav` 的 `env(safe-area-inset-bottom)` 在 iOS 生效、软键盘弹出时布局收缩。
2. **标题语义（P0）**：`AppLayout.tsx:282` 顶栏 `currentPageTitle` 由 `<h1>` 降级为 `<p aria-hidden="true">`，保留页面自身唯一 `<h1>`，修复屏幕阅读器大纲。
3. **触控目标（P0）**：`dialog.tsx:45` 关闭按钮用 `grid place-items-center h-11 w-11` 扩到 44×44，保留 `sr-only` 关闭文案与 Radix 语义。
4. **性能/适配（P1）**：删除 `globals.css:2` 的 `@import`（与 `index.html:12` link 重复且阻塞），改为仅保留 link 并加 `preload`；`100vh`→`100dvh`（`globals.css`/`ErrorBoundary`）；`:root` 增 `color-scheme: dark`。
5. **交互手感（P1/P2）**：全局 `@media (pointer: coarse)` 设 `touch-action: manipulation`、`-webkit-tap-highlight-color: transparent`；新增 `@media (prefers-contrast: high)` 用高对比 token 覆盖文字/边框。
6. **CI 回归（P2）**：新增 `jest-axe` 组件冒烟测试（`.test.tsx`）+ 在 `pnpm verify` 增加 axe 步骤，形成可访问性回归门禁，复用现有 `vitest.config.ts` 双项目结构。
7. **手动 QA（P3）**：用屏幕阅读器与浏览器移动模拟器走查，确认整改项生效、无新增阻断。

## 关键文件（将修改）

- `index.html`（viewport 元标签）
- `src/layouts/AppLayout.tsx`（顶栏 h1→p）
- `src/shared/components/ui/dialog.tsx`（关闭按钮命中区）
- `src/styles/globals.css`（@import、100dvh、color-scheme、touch-action、prefers-contrast）
- `src/shared/components/business/ErrorBoundary.tsx`（100dvh）
- `src/layouts/MobileNav.tsx`（安全区复核，配合 ui-ux-dev）
- 新增 `src/**/*.test.tsx`（jest-axe 冒烟）、`package.json` verify 脚本扩展

## 风险与回归控制

- 仅改全局/基础层文件，不触碰特性模块业务逻辑；`color-scheme`/`prefers-contrast` 用媒体查询隔离，不影响默认暗色外观。
- 每个单元改完跑 `pnpm verify`（typecheck+lint+test），`designTokenGuard` 守卫禁止霓虹/纯黑白，确保配色合规。
- 高对比模式仅新增 `@media` 块，不覆盖默认 token，避免影响正常视觉。

## Agent Extensions

### SubAgent

- **platform-dev**
- Purpose: 负责基础层修复——index.html viewport 元标签、AppLayout 顶栏语义、Dialog 关闭按钮命中区、globals.css 字体/视口/color-scheme、axe-core CI 门禁接入
- Expected outcome: 完成 P0 布局层缺陷与 P1 性能适配缺陷，并让自动化可访问性测试纳入 pnpm verify 回归
- **ui-ux-dev**
- Purpose: 负责设计/交互层修复——触控手感（touch-action/tap-highlight）、安全区与触控目标复核、prefers-contrast 高对比适配、P3 屏幕阅读器/键盘导航 QA
- Expected outcome: 移动端交互手感与可访问性达 WCAG 2.1 AA，高对比模式可用，手动 QA 无阻断性问题

### Skill

- **wcag-audit-patterns**
- Purpose: 为 P2/P3 提供 WCAG 2.2 审计与修复模式参考，校验整改项符合规范条款
- Expected outcome: 每项修复有对应 WCAG 依据，避免漏项
- **screen-reader-testing**
- Purpose: P3 用 VoiceOver/NVDA 验证屏幕阅读器兼容（标题大纲、焦点、live region）
- Expected outcome: 输出走查报告，确认双 h1 等问题已消除
- **webapp-testing**
- Purpose: 在真实浏览器移动模拟器验证 viewport-fit、软键盘、横竖屏、安全区表现
- Expected outcome: 提供可复现验证步骤与截图证据
