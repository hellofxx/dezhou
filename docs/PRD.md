## 1. 产品背景与目标

### 1.1 背景与问题陈述

#### 1.1.1 市场背景

德州扑克作为全球最流行的扑克变体（NLHE 为绝对主流），其玩家群体持续扩大：全球线上扑克市场 2024 年约 38.6 亿美元，预计 2030 年达 69 亿美元（年复合增长率 10.2%）。随着 GTO（博弈论最优）理论普及，玩家对**系统化训练工具**的需求持续攀升，移动端训练工具快速崛起，免费增值（Freemium）模式已被头部产品验证可行。

#### 1.1.2 用户痛点（问题陈述）

经社区访谈与论坛调研（详见 §3.2），扑克学习者在现有工具与内容生态中面临 8 项核心痛点，其中 4 项最为突出：

| 优先级 | 痛点 | 问题陈述 |
|---|---|---|
| P0 | 学习路径缺失 | 玩家不知道"先学什么、后学什么"，内容庞杂但无体系引导，容易在中途放弃 |
| P0 | 工具门槛高 | PioSolver 等专业工具配置复杂、价格昂贵（$49-$65/月）、学习曲线陡峭 |
| P1 | 知识碎片化 | 论坛、视频、书籍中的知识分散，难以整合为可执行的决策能力 |
| P1 | 缺乏反馈机制 | 实战与练习中无法即时知道某个决策是否正确、错在哪、损失多少 |

其余痛点（复盘效率低、练习不持续、中文资源匮乏、费用门槛）详见 §3.2 完整调研表。

#### 1.1.3 机会窗口

1. **中文市场空白**：主流竞品（PokerTracker 4 / Flopzilla / GTO Wizard）均不支持中文，高质量中文扑克教学内容稀少
2. **一体化整合机会**：竞品功能割裂（分析 / 训练 / 追踪分属不同产品），尚无产品同时覆盖"训练 + 分析 + 追踪"完整学习闭环
3. **移动与离线趋势**：移动优先 + PWA 离线能力可覆盖通勤、差旅等碎片化训练场景
4. **免费准入**：零后端、零成本部署使全功能免费成为可持续的竞争壁垒

### 1.2 产品定位

一款**纯前端、零后端依赖**的德州扑克系统性训练工具，通过交互式练习、即时反馈与数据可视化，帮助各层级扑克玩家以结构化方式提升决策能力与策略水平。

**一句话定位**：面向中文扑克玩家的"零门槛、系统化、可量化的全栈训练场"。

### 1.3 范围界定

#### 1.3.1 In Scope（本产品范围内）

- 六大训练核心：手牌范围记忆、底池赔率与 EV 计算、GTO 决策模拟、历史牌局复盘、扑克谜题、快速训练
- 两大学习路径：策略学院（实践应用）与理论学院（理论构建），含课程体系、Drill、测验与认证
- 留存激励体系：Streak 连续训练、冻结卡、ELO 能力分级、成就徽章、今日任务、排行榜、进步回放
- 反馈教练体系：五级反馈分类、导师人格化、情绪管理、GTO 偏差检测、间隔重复（SRS）
- 平台能力：PWA 离线、中英双语国际化、新手引导、帮助中心、开发者选项
- 变体支持：标准德州（NLHE）为主，短牌（Short Deck）与单挑（Heads-Up）作为独立变体课程体系

#### 1.3.2 Out of Scope（明确不在范围内）

- 实时对战 / 在线扑克室 / 真实货币游戏
- 实时 HUD（桌面端牌桌叠层显示，见 §4 竞品对比）
- 服务端账号体系、云同步、跨设备数据漫游（纯本地存储）
- 在线多人排行榜（当前为本地模拟）、社区 / 社交功能
- 实时 GTO 求解器（采用预计算方案，见 TDD）
- 扑克以外的变体（如 PLO）训练内容

### 1.4 产品目标

#### 1.4.1 用户学习目标（产品使命转化为用户可感知的结果）

1. 掌握 6-max 各位置的标准翻前开牌范围（UTG/HJ/CO/BTN/SB/BB）
2. 熟练计算底池赔率与期望值（EV），做出 +EV 的跟注/弃牌决策
3. 理解 GTO 策略的基本原则并应用于实战场景
4. 能够独立复盘历史牌局，识别关键决策点的失误并用 GTO 标准校准
5. 建立持续训练习惯（Streak），在能力维度（ELO 五维）上获得可量化成长

#### 1.4.2 产品业务目标

1. **北极星指标**：单用户周均完成 ≥3 次有效训练（有效 = 形成训练记录并计入连续训练）
2. **学习有效性**：首次训练到第 10 次训练的正确率提升 ≥15 个百分点
3. **留存**：7 日留存 ≥40%，30 日留存 ≥20%
4. **覆盖深度**：使用 ≥2 个训练模块的用户占比 ≥50%
5. **激励激活**：至少解锁 1 个成就徽章的用户占比 ≥60%

### 1.5 成功指标（关键指标集）

| 类别 | 指标名称 | 目标值 | 度量方式 |
|---|---|---|---|
| 训练完成度 | 单次训练完成率（进入会话→正常走完结算） | ≥ 80% | 训练会话事件 |
| 学习效果 | 首次 vs 第 10 次训练正确率提升 | ≥ 15 个百分点 | ELO/正确率历史 |
| 用户留存 | 7 日留存率 | ≥ 40% | Streak 活跃度 |
| 用户留存 | 30 日留存率 | ≥ 20% | Streak 活跃度 |
| 使用频率 | 周活跃训练次数 | ≥ 3 次/用户 | 训练事件计数 |
| 功能覆盖 | 使用 ≥ 2 个训练模块的用户占比 | ≥ 50% | 模块覆盖去重 |
| 成就解锁 | 至少解锁 1 个成就的用户占比 | ≥ 60% | 成就系统数据 |

> **度量口径**：所有指标基于本地训练事件统计，无服务端埋点；"训练完成"定义以 `progress` 模块的训练记录（trainingEvents）为唯一事实源。

## 2. 用户角色定义

### 2.1 角色总览

| 角色 | 一句话描述 | 学习阶段 | 优先级 |
|---|---|---|---|
| 零基础新手 | 刚接触德扑，规则尚不熟，需要体系化入门引导 | 0-L1 | P0 |
| 休闲进阶玩家 | 有实战经验但决策靠感觉，希望系统化提升 | L1-L4 | P0 |
| 重度钻研玩家 | 目标明确的训练者，追求量化成长与针对性补强 | L4-L8 | P1 |
| 内容消费者/教练 | 需要标准范围、课程材料做教学展示的辅助角色 | 全域 | P2 |

### 2.2 角色详细定义（Persona）

#### Persona A：零基础新手

| 维度 | 内容 |
|---|---|
| 背景特征 | 18-30 岁，被朋友带入牌局或受德州扑克影视/直播吸引；可能玩过几次现金局，从未系统学习 |
| 使用场景 | 第一次打开应用，手机端为主，通勤或睡前碎片时间 |
| 核心目标 | ① 知道该从哪里开始学 ② 快速理解基本规则与概念 ③ 不因挫败感放弃 |
| 主要痛点 | 学习路径缺失（"不知道先学什么"）、术语陌生、害怕犯错丢脸 |
| 关键任务 | 完成新手引导（§5.7）→ 首次微训练成功收尾 → 入门课程（L1）→ 基础 Drill（§5.10）→ 3 分钟快速训练建立习惯 |
| 成功标准 | 完成 Onboarding；首周完成 ≥3 次训练；解锁首个成就；Streak ≥3 天 |
| 对应功能 | §5.7 引导 / §5.10 Drill / §5.16 策略学院 L1-L2 / §5.11 快速训练 / §5.8 Streak |

#### Persona B：休闲进阶玩家

| 维度 | 内容 |
|---|---|
| 背景特征 | 25-40 岁，线上线下混合游戏，NL2-NL100 级别；每周 2-5 次牌局；有改进意愿但时间有限 |
| 使用场景 | 训练时间相对固定（晚间/周末），桌面端为主，追求单次训练效率 |
| 核心目标 | ① 修补明显漏洞（范围、赔率、C-Bet）② 理解 GTO 基本原理并落地 ③ 看到量化进步 |
| 主要痛点 | 知识碎片化、实战后不知道错在哪、缺乏即时反馈、练习不持续 |
| 关键任务 | 范围训练限时测验 → 五级反馈复盘错题 → 理论学院 T4-T5 补数学 → 牌局导入复盘 + GTO 偏差检测 → 每日快速训练维持 Streak |
| 成功标准 | ELO 综合分持续上升；第 10 次训练正确率较首次提升 ≥15 个百分点；能独立复盘一手牌并定位最大 EV 损失点 |
| 对应功能 | §5.1-5.5 / §5.13 ELO / §5.23 GTO 偏差 / §5.27 理论学院 / §5.14 SRS |

#### Persona C：重度钻研玩家

| 维度 | 内容 |
|---|---|
| 背景特征 | 职业或半职业，NL200+ 或锦标赛玩家；熟悉 GTO 术语，已使用过 GTO Wizard 类工具 |
| 使用场景 | 长时段专注训练（30-60 分钟），桌面端；针对特定 Spot 反复训练 |
| 核心目标 | ① 精细化训练特定场景（短筹码、ICM、剥削调整）② 追踪长期数据趋势 ③ 保持竞技状态 |
| 主要痛点 | 常规训练已无新鲜感、需要更高难度的挑战与深度内容、碎片化训练价值低 |
| 关键任务 | GTO Spot 练习 → 主题谜题（短筹码/ICM）→ 高级课程（L6-L8/本土盈利路径）→ 牌局 GTO 偏差汇总 → 长 Streak 里程碑守护 |
| 成功标准 | 达到高级/专家段位；GTO Spot 平均 EV 损失持续收敛；完成 L6-L8 全部课程 |
| 对应功能 | §5.3 GTO / §5.12 谜题 / §5.17 本土路径 / §5.23 偏差检测 / §5.13 ELO 段位 |

## 3. 用户调研与市场需求

### 3.1 扑克玩家画像

根据行业调研数据，扑克玩家群体具有以下特征：

- **年龄分布**：线上扑克玩家平均年龄约 29 岁，超 75% 的玩家年龄在 35 岁以下；18-25 岁群体占比超 40%，是最活跃的年龄段
- **性别比例**：男性玩家占约 90%，女性约 10%；线上环境女性比例略高于线下锦标赛（线下女性参赛率通常低于 5%）
- **地域分布**：美国、德国、法国为全球前三大扑克市场；中国、巴西等新兴市场增长迅速
- **游戏偏好**：无限注德州扑克（NLHE）为绝对主流，其次是底池限注奥马哈（PLO）

### 3.2 用户痛点调研

通过社区访谈与论坛调研，扑克学习者普遍面临以下痛点：

| 痛点类型 | 具体描述 | 严重程度 |
|---|---|---|
| 学习路径缺失 | "我不知道应该从哪里开始学，应该先学什么" | ★★★★★ |
| 工具门槛高 | PioSolver 等专业工具配置复杂、价格昂贵、学习曲线陡峭 | ★★★★★ |
| 知识碎片化 | 论坛帖子、YouTube 视频、书籍中的知识分散，难以体系化 | ★★★★ |
| 缺乏反馈机制 | 实战中无法即时知道某个决策是否正确 | ★★★★ |
| 复盘效率低 | 手动记录和分析牌局耗时费力，难以坚持 | ★★★★ |
| 练习不持续 | 缺乏系统性的训练计划和激励机制，容易半途而废 | ★★★ |
| 中文资源匮乏 | 高质量中文扑克教学内容稀少，翻译质量参差不齐 | ★★★ |
| 费用门槛 | 主流训练工具价格从 $65-$49/月不等，对休闲玩家负担较重 | ★★★ |

### 3.3 市场需求分析

- **全球线上扑克市场**：2024 年市场规模约 38.6 亿美元，预计 2030 年达 69 亿美元，年复合增长率 10.2%（Grand View Research）
- **训练工具需求增长**：随着 GTO 理论普及，玩家对系统化训练工具的需求持续攀升；德国等市场玩家尤其偏好策略分析型工具
- **移动端趋势**：移动优先策略成为吸引多元化用户群体的关键；NTPoker 等移动端 GTO 训练器快速崛起
- **免费增值模式主流化**：GTO Wizard 等头部产品采用免费层 + 付费订阅模式（Pro $29/月、Elite $49/月），验证了 Freemium 模式的可行性

### 4.3 竞品详细分析

#### 4.3.1 PokerTracker 4

**产品简介**：运营超 15 年的老牌扑克分析软件，以实时 HUD（抬头显示器）和详尽的数据报告闻名，是线上职业牌手的标配工具。

**核心功能**：
1. 实时 HUD：在牌桌上即时显示对手数据（VPIP、PFR、AGG 等数百项指标）
2. 牌局数据追踪：自动记录所有牌局数据，支持多维度筛选
3. 多样化分析报表：胜率曲线、位置分析、摊牌分析等
4. 内置牌局重播：逐步回顾历史牌局决策
5. NoteTracker：自动记录对手行为笔记

**定价**：Hold'em 小注额版 $64.99 / 全注额版 $99.99 / Hold'em + Omaha 全注额版 $159.99；一次购买终身使用，首年免费更新，之后可选年费 $29.99 维护

**优势**：数据深度业界领先、实时 HUD 独一无二、长期口碑积累强
**劣势**：纯分析工具不含训练功能、学习曲线陡峭、不支持中文、价格较高

#### 4.3.2 Flopzilla

**产品简介**：专注于范围 vs 牌面交互分析的计算工具，帮助玩家快速理解特定范围在不同翻牌面上的击中分布。

**核心功能**：
1. 范围输入与可视化：13×13 矩阵选择起手牌范围
2. 翻牌面分析：输入翻牌后自动计算范围击中分布（顶对、中对、听牌等）
3. 赢率计算：单挑与多路底池赢率计算
4. 过滤器：按牌型过滤查看范围子集
5. FlopzillaPro 升级版：支持分组模式、多人模式、GTO+ 导入导出

**定价**：一次性购买，已注册用户免费升级至 Pro 版

**优势**：计算速度极快（几乎实时）、界面直观、价格亲民
**劣势**：不提供 EV 或策略建议、无法建立决策树、翻前实用性有限、仅 Windows

#### 4.3.3 GTO Wizard

**产品简介**：当前最先进的云端 GTO 训练平台，被誉为"PioSolver 的大众化入口"，将专业求解器结果以交互式训练形式呈现。

**核心功能**：
1. 云端 GTO 求解：基于 PioSolver 精度的预计算方案，秒级加载
2. 交互式训练：模拟真实牌局，即时反馈决策正确性与 EV 损失
3. 动态范围查看器：实时显示 GTO 推荐频率与范围构成
4. Leak Finder：上传 Hand History，AI 自动对比 GTO 偏差
5. 每日挑战 + 积分排行榜
6. 单街训练：专注 Flop/Turn/River 特定街道

**定价**：Free（每日 10 次查询 + 基础训练）/ Pro $29/月 或 $249/年 / Elite $49/月

**优势**：功能最全面的 GTO 学习平台、界面现代、社区活跃
**劣势**：仅支持 NLHE、纯 GTO 导向无剥削策略、依赖网络、高级功能价格较高

### 5.1 手牌范围记忆训练（range-trainer）

**用户故事**

> 作为休闲进阶玩家，我希望通过 13×13 范围矩阵可视化记忆各位置的起手牌范围，以便在实战中快速识别特定位置的开池/防守范围，减少翻前决策的犹豫与错误。

**功能规格**

| 编号 | 功能点 | 描述 |
|---|---|---|
| 5.1.1 | 范围可视化 | 13×13 矩阵展示起手牌范围，悬停单元格即时显示手牌详情（对子 / Ax 同花 / 两高张等）与范围占比 |
| 5.1.2 | 位置维度 | 支持 UTG / HJ / CO / BTN / SB / BB 六位置；位置渐进解锁，解锁阈值以 `src/features/range-trainer/constants.ts` 的 `POSITION_UNLOCK_THRESHOLDS` 为唯一事实源 |
| 5.1.3 | 训练模式 | 翻前范围记忆 Quiz：给定位置与场景，用户从候选范围/动作中选择，即时反馈 |

| 5.1.5 | 变体适配 | 支持标准 / 短牌 / 单挑三种变体，变体定义与配置以 `src/shared/types/elo.ts` 的 `PokerVariant` / `VARIANT_CONFIG` 为唯一事实源 |

**验收标准**
- 用户可完成至少 10 道范围记忆题并获得五级反馈（§5.9）
- 锁定位置在范围选择器中不可选，达到阈值后立即可用

### 5.9 五级决策反馈系统（跨模块核心机制）

**用户故事**

> 作为所有训练用户，我希望答题后获得统一、可理解的分级反馈（最优/正确/不精确/错误/严重错误），以便清楚知道每个决策距离最优策略有多远，而不是简单的对错。

**功能规格**

| 编号 | 功能点 | 描述 |
|---|---|---|
| 5.9.1 | 五级评级 | `DecisionGrade = best / correct / inaccuracy / wrong / blunder`；评级函数 `calculateGrade(evLoss)` 为唯一评级入口，阈值常量 `GRADE_THRESHOLDS` 与边界规则（归入更严重等级）以 `src/shared/types/decisionFeedback.ts` 为唯一事实源 |

**验收标准**

## 6. 非功能需求

### 6.1 性能需求

| 编号 | 指标 | 目标值 |
|---|---|---|
| 6.1.1 | 首屏加载 | 主要页面首屏可交互时间（TTI）≤ 2.5s（中端移动设备，离线可放宽） |
| 6.1.2 | 路由切换 | 页面 chunk 按路由懒加载，切换无白屏等待 > 1s |
| 6.1.3 | 交互响应 | 答题反馈 / 图表渲染等核心交互响应 ≤ 300ms |
| 6.1.4 | 包体控制 | 核心代码与大型数据文件分包管理，避免首屏阻塞（分包策略以 `vite.config.ts` 为唯一事实源） |
| 6.1.5 | 大数据量 | 牌局导入（>1MB）与分析不阻塞主线程（worker 方案见 TDD）；IndexedDB 查询百级牌局记录保持流畅 |

### 6.2 安全需求

| 编号 | 需求 | 说明 |
|---|---|---|
| 6.2.1 | 无账号无凭证 | 产品零后端依赖，不收集登录凭证、支付信息等敏感数据；不存在服务端泄露面 |
| 6.2.2 | 输入校验 | 全部用户输入（牌局文本导入 / 表单 / 搜索）经解析与校验，防注入类异常；牌局解析器对非法/恶意输入安全降级（解析器健壮性测试守护） |
| 6.2.3 | XSS 防护 | 用户可导入的文本内容一律按纯文本/安全 HTML 渲染，禁止 `dangerouslySetInnerHTML` 直插不可信内容（以共享渲染组件实现为准，见 TDD） |
| 6.2.4 | 本地存储边界 | localStorage / IndexedDB 仅存训练数据与偏好，不存任何外部身份信息；导出文件不含可执行内容 |
| 6.2.5 | 依赖供应链 | 依赖通过 pnpm lockfile 锁定版本，禁止引入未评估的新依赖（新增依赖须评估 bundle 体积，见 AGENTS.md §技术栈） |
| 6.2.6 | Service Worker 安全 | 离线缓存仅覆盖自身静态资源，不缓存第三方不可信内容（见 §5.20） |

### 6.3 可访问性

- 全部交互元素满足 WCAG 2.1 AA 对比度要求（色彩设计约束见 §8.1）
- 键盘可完整操作：焦点可见、Tab 顺序合理、快捷操作有提示（§8.3）
- 触控目标尺寸 ≥ 标准可点区域（移动端，配合响应式 §6.4）
- 语义化标签与 ARIA 状态用于反馈/加载/错误提示，屏幕阅读器可理解训练流程
- 动效遵循 prefers-reduced-motion 降级原则

### 6.4 浏览器兼容与响应式

- 支持最新两个大版本的 Chrome / Edge / Firefox / Safari 及同内核移动浏览器
- 响应式断点：移动 (<768px，底部导航) / 平板 / 桌面；核心训练场景移动端可用
- 移动端适配包括但不限于：底部导航、触控热区、字号缩放不破版（响应式细则见设计约束 §8 与 DESIGN_LANGUAGE）

### 6.5 数据持久化与隐私

| 编号 | 需求 | 说明 |
|---|---|---|
| 6.5.1 | 训练数据 | 训练记录 / 进度 / ELO / Streak / SRS 等经 zustand persist 持久化到 localStorage（版本化迁移，禁止裸调 localStorage API，规则见 AGENTS.md） |
| 6.5.2 | 牌局大数据 | 牌局文件与解析结果存 IndexedDB（大数据场景） |
| 6.5.3 | 数据导出 | 提供训练数据导出（JSON），用户可备份/迁移，卸载前可保留 |
| 6.5.4 | 隐私默认 | 数据全部本地存储，不上传任何云端；排行榜为纯本地（§5.6.3） |

### 6.6 可靠性与离线

- 核心训练与进度记录在离线状态下完整可用，联网恢复后无需额外同步（PWA 离线见 §5.20）
- 持久化写入失败（存储配额等）有降级提示，不静默丢数据
- Service Worker 激活时清理旧版本缓存，避免新旧版本资源混用（版本机制见 §5.20）

## 7. 用户旅程与核心闭环

### 7.1 完整用户旅程（新人视角）

> 首次打开 → Onboarding 偏好采集（§5.7）→ 定向起点推荐 → 基础训练（范围记忆 / 赔率 Quiz）→ 五级反馈 + 导师文案 → 数据进入进度 Dashboard → 连续打卡 Streak → 错题进入 SRS → 薄弱点分析推送课程推荐（§5.24）→ 课程学习（策略学院 / 理论学院）→ 章末小测 → 进阶变体训练（短牌 / 单挑）→ 实战牌局导入复盘（GTO 偏差）→ 持续训练形成习惯闭环。

### 7.2 核心闭环验收场景

**闭环一：训练 → 反馈 → 进度（学习-数据闭环）**

1. 用户在任一训练模块完成答题
2. 系统返回五级评级（§5.9）与导师文案（§5.18），wrong/blunder 触发"去复习"链接
3. 训练事件经事件总线上报（§5.5.6），Streak / ELO / SRS / Emotion / 成就同步更新
4. Dashboard 聚合展示，薄弱点分析更新

**验收（可验证）**：完成 1 次答题后（1）评级正确；（2）Dashboard 对应计数 +1 且同题去重（3）成绩影响 ELO 与答题记录（4）答错题出现在次日 SRS 复习队列。

**闭环二：理论 → 实践 → 复习（学习-巩固闭环）**

1. 理论学院章节学习 → 章末小测（§5.27）
2. 小测薄弱项桥接到策略学院 / 训练模块（§5.24）
3. 训练模块错误题关联课程"去复习"回到理论/策略内容（§5.9）

**验收（可验证）**：理论小测答错的考点，在横向推荐中出现对应训练入口；训练答错的题，"去复习"目标课程可达。

**闭环三：打卡 → 保护 → 激励（习惯闭环）**

1. 连续训练形成 Streak（§5.8）
2. 中断风险由冻结卡保护（碎片合成 §5.21）
3. 成就 / 今日任务 / 排行榜持续提供激励（§5.6）

**验收（可验证）**：断连日有冻结卡则不中断计数；7 天连续训练自动奖励冻结卡；成就达成持久化不重复触发。

## 8. 设计约束

- **色彩体系**：四层色彩 token（`--felt-*` 牌桌绿系 / `--ivory-*` 象牙白系 / `--brass-*` 黄铜金系 / `--walnut-*` 胡桃木系），暗色为默认；禁止硬编码颜色、禁止霓虹调色板与纯黑白（唯一权威源：`src/styles/globals.css`，由 designTokenGuard 测试守护）
- **字体与排版**：全局字体栈与字号规范遵循 DESIGN_LANGUAGE（写明的唯一权威源：`poker-ui-demo/DESIGN_LANGUAGE.md`），保证中西文混排质量
- **键盘与快捷操作**：核心训练提供键盘快捷键（选择 / 提交 / 下一题），快捷键有可见提示
- **纯前端架构**：零后端依赖；不引入需要服务端的第三方能力；规则与边界见 AGENTS.md
- **教育 UX 七原则**：即时反馈 / 渐进难度 / 错误可见可修复 / 可重复练习 / 进度可视化 / 反馈人性化（导师人格 §5.18）/ 学习路径清晰；所有训练模块遵循，具体落地见各模块验收标准
- 移动/平板/桌面三端响应式视觉一致性由 `ui-ux-dev` 复核流程守护（质量清单以 DESIGN_LANGUAGE 为准）

## 12. 文档治理与维护约定

### 12.1 三层文档职责分离（与 TDD / CHANGELOG 的分工）

| 文档 | 职责 | 更新时机 | 唯一事实源声明 |

### 12.2 单一事实源引用原则（AI 协作友好）

- 本文档描述跨模块依赖与阈值状态时，一律**明确指向单一事实源**（代码路径或特定 store），不复制数值副本：
  - 状态：五大系统以 `src/features/progress/store.ts` 为唯一事实源（§5.5.6）
